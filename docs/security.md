# Security and privacy

RANterra is a local, single-user research application. **Use synthetic laboratory identities only. Never import real SIM credentials, production keys or personal subscriber records.** Public deterministic lab credentials and RAND values are intentionally reproducible and provide no production subscriber security.

## Trust boundaries

The UI validates command shapes; the worker enforces revisions and a bounded 256-command queue; Rust independently validates scenarios and protocol inputs before replacing state. Native engine code has no browser dependency. Imported strings render as React text. Scenario schemas reject unknown fields and secret-bearing extensions. Separate UE/AMF contexts enforce authentication, integrity, counts and state transitions; no frontend flag grants registration. Synthetic cryptographic vectors use zeroizing wrappers, but compiler/runtime/browser copies and crash dumps are not guaranteed to be erased.

The emulated AMF/AUSF/UDM, UE, SMF and UPF share a WASM instance, so this is not a security-isolation testbed. There is no secure element, hosted login, tenant boundary, TLS/SBI/SCTP service or actual internet forwarding. Anyone controlling the browser or source can inspect lab secrets. Logs contain wire payloads and synthetic identity data but do not export K, OPc, derived keys or reusable NAS contexts. Do not put sensitive data in labels, packets or imported geometry.

Bounds include 16 cells, 128 UEs, 600 buildings, 15,000 geometry vertices, 100 vertices per ring, 128 waypoints per UE, bounded packet/ASN.1 parsing, 16,384 log records, and finite numeric/radio ranges. Geographic responses are streamed with byte limits and timeouts. Invalid loads leave the existing engine intact. Session/TEID validation rejects stale traffic. Worker recovery recreates WASM and reloads configuration; it does not resurrect security keys. IndexedDB errors are reported, cache failures are recoverable, and named copies/cache entries are bounded. Storage-quota behavior depends on the browser and has not been stress-tested to exhaustion.

## Browser/deployment controls

`public/_headers` contains CSP, MIME sniffing prevention, referrer and permissions policies. CSP allows WebAssembly compilation, MapLibre worker blobs and inline styles required by the map/UI; it forbids arbitrary inline script. Update provider origins deliberately when configuring another map service. Serve HTTPS, correct JavaScript/WASM MIME types, immutable hashed assets and uncached HTML/config. No telemetry, analytics, cookies or remote subscriber database are added.

Map/search/geometry providers receive the browser IP, requested region and search text. Configuration is public: never put private API secrets in `config.json`. Provider-approved browser tokens must be origin-restricted. Default search is disabled. Disabling all provider URLs leaves already-loaded computation and bundled geometry local. There is no service worker or offline tile prefetching.

[OWASP ASVS 5.0](https://owasp.org/www-project-application-security-verification-standard/) is the verification reference for applicable input-validation, browser, configuration, dependency and privacy controls. The internal Level 1 requirement-by-requirement assessment is recorded below; it is not certification or a penetration test. Sanitizer fuzzing and an extended lifecycle soak have run, but not a running full mobile-core interoperability test.

## Dependencies

Both lockfiles are retained. `npm audit`, `cargo audit`, and `node scripts/check-licenses.mjs` are CI gates. At local verification npm reported zero known vulnerabilities; Rust reported no known vulnerabilities and one unmaintained transitive package warning (`paste` 1.0.15, RUSTSEC-2024-0436). Track upstream replacement; this warning is not hidden by an ignore rule. The license inventory covers 426 locked packages (including isolated fuzz tooling) and contains only reviewed permitted expressions. No AGPL source was integrated. License expression checks do not replace retaining upstream notices and a legal review for redistribution; see `docs/DEPENDENCIES.json`.

Report suspected issues privately to the repository maintainer before publishing details. No dedicated security contact or formal response SLA has been established for this candidate.


Portable recordings are bounded (4 MB, 4,096 commands, one hour) and deny unknown fields. Replay occurs in a candidate engine and only replaces the live instance after state-digest verification. Failed command mutations roll back by deterministic reconstruction. The digest is an integrity/compatibility check, not an authenticated signature. Checkpoints reconstruct synthetic lab security state without storing keys. Real credentials remain prohibited. Quota failure is now browser-tested by injecting a QuotaExceededError into the run store and verifying export remains usable; this is not a physical disk-exhaustion test.

The standalone free5GC validation executable uses nine linked development-only dependencies (including the test graph), with reviewed Apache-2.0/MIT/BSD-2-Clause/BSD-3-Clause notices and hashes under `validation/free5gc`. It never ships in browser assets. Runtime audits remain enforced. The npm lockfile now includes the missing luma.gl WebGPU peer dependencies; `.npmrc` prevents a local legacy-peer setting from hiding clean-install defects.


Validation-only audit exception: [GO-2022-1083](https://pkg.go.dev/vuln/GO-2022-1083) reports malformed-input panics in free5GC APER, with no fixed release listed. The checker consumes locally generated bounded fixtures and endpoint responses in separate test processes, has no network listener, and turns panics into test failures. Do not use this validator to serve or ingest arbitrary uploaded traffic. It is absent from browser/native application dependencies. `python3 scripts/audit-validation.py` pins Go 1.27.2 and govulncheck 1.9.0, retains the JSON audit, reports this exception visibly and fails on any additional reachable advisory. The initial system-Go 1.23.2 scan also found a standard-library advisory; the pinned 1.27.2 scan removed that finding. This validation tool is not represented as vulnerability-free.

## Endpoint-validation hardening

The independent peer exposed and regression-tested a plaintext Security Mode Command bypass, now fixed. Invalid N1 container types, invalid IPv4/ICMP replies, unknown transport contexts and JavaScript IDs that would wrap to u32 are rejected. Malformed transport is isolated per frame; in-flight echoes have a 2,000 ms virtual cleanup deadline. The deterministic mutation campaign is supplemented by 837,065 coverage-guided sanitizer inputs and 16,384 real-WASM lifecycle/replay/free cycles. These finite campaigns are not proof that every malformed input or leak has been eliminated. See [validation scope and remaining gaps](interop-validation.md).

AUTS is verified with constant-time MAC-S against the outstanding RAND; invalid MACs, cross-subscriber/wrong-RAND data and consumed-challenge replay cannot establish keys. SQN advancement rejects 48-bit exhaustion. The synthetic USIM uses monotonic freshness, not a production operator's IND/window policy. An outstanding authentication challenge may reuse its cached RES* until Security Mode succeeds; the cache is zeroized on clear/failure/success. The bounded `SqnOutOfSync` laboratory setting does not import credentials. Shared SMF state rejects traffic before N2 acknowledgement and once release starts, validates gNodeB-provided downlink TEIDs, and keeps reservations until release completes or expires. Normal initial-registration timers and one encoded N2 failure cause are now supported; other timer variants and failure procedures remain outside scope.

## Applicable ASVS assessment and maintenance policy

The application-specific [ASVS 5.0.0 Level 1 assessment](asvs-assessment.json) covers every Level 1 requirement with an evidence reference or explicit applicability decision. It is an internal assessment, not certification. Selected higher-level browser controls (CSP, nosniff, frame-ancestors and referrer policy) are also configured and tested. Web accounts, JWT, OAuth, multi-tenant authorization and server upload paths do not exist. Laboratory 3GPP cryptography is explicitly outside any production-secret protection claim. HTTPS, certificate and HSTS enforcement remain hosting gates.

Triage newly disclosed runtime critical/high vulnerabilities within 48 hours; block release until patched or exposure eliminated. Triage medium findings within seven days and remediate within 30 days; low/maintenance issues within 90 days. Recheck locked dependency advisories before every candidate and monthly during maintenance. These are project targets, not a hosted response SLA or an automation already scheduled. Current explicitly assessed exceptions: unmaintained transitive paste (track upstream replacement), and GO-2022-1083 only in the isolated development validator with no listener or user-upload path. Neither exception permits new reachable runtime advisories.

The follow-up fixes transactional configuration loading, disallows provider credentials/scheme-relative URLs/backslashes, keys geometry cache entries by provider, serializes library-capacity checks in one IndexedDB transaction, and closes storage connections on version changes. Browser tests inject denied storage and quota errors and verify text-only rendering of malicious labels. Runtime failures remain visible without discarding exportable experiments.
